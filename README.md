# Simple MMORPG

IOCP 서버 위에 섹터 관리, DB 연동, Lua 스크립트 AI 등 MMORPG의 핵심 시스템을 직접 구현한 2D MMORPG입니다. 게임 서버 프로그래밍 수업의 텀프로젝트로 진행한 **1인 프로젝트**입니다.

- **개발 기간**: 2024.03.04 ~ 2024.06.18
- **개발 인원**: 1명
- **담당**: 기획, 서버 구축, 데이터베이스 연동, 콘텐츠 제작

## 게임 기능

- 이동(1초 2회), 공격(1초 1회), 채팅
- 3종 몬스터 (고정형, 로밍형) 및 30초 후 부활
- 레벨, 경험치, 체력 시스템 (레벨에 따라 공격력·최대 체력 증가)
- 장애물 무작위 배치 (중복 배치 방지)
- 사망, 레벨 업, 공격, 피격 시스템 메시지

## 주요 구현 내용

### 1. IOCP 기반 비동기 서버

- **문제**: 접속마다 스레드를 두는 블로킹 I/O 모델은 동시 접속자가 늘면 스레드 관리 비용 때문에 확장에 한계가 있습니다.
- **해결**
  - `AcceptEx` 비동기 접속과 `GetQueuedCompletionStatus` 기반 완료 이벤트 처리 구조로 설계했습니다.
  - 워커 스레드 풀을 고정 운용하고, 세션 단위 컨텍스트로 네트워크 처리와 게임 로직을 분리했습니다.
  - NPC 이동, 부활, 플레이어 회복 같은 작업도 IOCP 작업 타입으로 등록해 워커 스레드가 처리합니다.
- **결과**: 객체 12만 개, 동시 접속 5,000명 스트레스 테스트에서 CPU 점유율 5% 미만으로 안정적으로 동작했습니다.

### 2. 섹터 기반 시야 처리

- **문제**: 모든 객체를 서로 비교하는 시야 처리는 동시 접속자가 늘수록 연산량이 급증해 서버 부하로 직결됩니다.
- **해결**
  - 2000 x 2000 맵을 고정 그리드 섹터로 나누고, 섹터마다 컨테이너와 뮤텍스를 따로 두었습니다.
  - 객체가 이동해 섹터가 바뀌면 재등록하고, 주변 3 x 3 섹터만 스캔해 시야와 충돌 후보를 구합니다.
  - 새로 보이는 객체는 추가 패킷, 시야에서 사라진 객체는 제거 패킷, 계속 보이는 객체는 이동 패킷을 보냅니다.
- **결과**: 전역 비교 대비 시야 처리 연산량 95% 이상 감소. 같은 CPU로 더 많은 객체를 수용할 수 있게 되었습니다.

### 3. 타이머 기반 NPC 처리

- `concurrent_priority_queue`에 실행 시각과 함께 이벤트(NPC 이동, 부활, 회복 등)를 넣고, 타이머 스레드가 시각이 된 이벤트를 IOCP로 넘깁니다.
- 플레이어 시야 안에 있는 NPC만 깨워 움직이도록 해 불필요한 연산을 줄였습니다. 여러 스레드가 같은 NPC를 동시에 깨우지 않도록 활성 상태를 `atomic_compare_exchange`로 관리합니다.

### 4. DB 연동 및 데이터 영속성 (MSSQL, ODBC)

- **문제**: 재접속 시 이전 상태를 복구해야 하고, 서버 장애 시 데이터 유실 위험이 있으며, 여러 스레드가 DB에 동시에 접근합니다.
- **해결**
  - ODBC API로 MSSQL과 연동하고, DB 접근 로직을 `CDataBase` 클래스로 캡슐화했습니다.
  - DB 작업을 큐에 넣고 별도 DB 스레드가 처리해 디스크 I/O가 게임 로직을 막지 않도록 했습니다.
  - 로그인 시 유저 정보를 불러오고(없으면 생성, 중복 로그인은 실패 처리), 5초마다 및 사망·경험치 획득 시 저장합니다.
- **결과**: 주기적인 DB 저장 중에도 실시간 응답성을 유지했고, 재접속 시 위치, 상태, 레벨이 정상 복구되는 것을 확인했습니다.

### 5. Lua-C++ 바인딩 기반 몬스터 AI

- NPC마다 Lua 상태를 만들고, Lua에서 호출할 C++ API(`API_get_x`, `API_get_y`, `API_ChangeStat`)를 등록했습니다.
- Lua 스크립트는 공격 조건만 판단하고, 조건이 맞으면 C++ API를 호출해 실제 공격과 HP 갱신을 처리합니다.
- 서버 핵심 로직은 C++에 두고 판단 로직만 스크립트로 분리해, 컴파일 없이 AI 동작을 바꿀 수 있는 구조를 검증했습니다.

### 6. 공격·이동 쿨타임 검증

- 마지막 패킷 수신 시각을 기록해 정해진 간격보다 빠른 요청은 서버에서 무시합니다.
